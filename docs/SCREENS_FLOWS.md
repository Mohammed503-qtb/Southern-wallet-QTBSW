# 1. المقدمة

## 1.1 الغرض

هذه الوثيقة هي المرجع الوحيد لتصميم وتنفيذ **كل شاشات تطبيق محفظة الجنوب وتدفقات المستخدم داخلها**. تحدد:

- **كتالوج الشاشات** بمعرفات `SC-01..SC-57` موزعة على المجموعات الأربع عشرة من SRS §7.2، بتغطية كاملة لقائمة Master PLAN §85 (35 شاشة إلزامية) صفر نواقص.
- **الحالات الإلزامية** لكل شاشة مالية (SRS §7.3 + Master §95) والخريطة الموحدة للحالات العالمية الثماني (Master §110).
- **خريطة التنقل** (الجذر + Bottom Navigation + الـStacks + Deep Links) وفق Master §55 و§92.
- **15 تدفقاً رئيسياً** بمعرفات `FL-01..FL-15` بخطوات مرقمة وقرارات متفرعة، بنفس أسلوب Master PLAN.

الجمهور: مصممو UX/UI، مهندسو Flutter (بناء الشاشات دون اختراع سلوك)، صاحب المنتج (اعتماد)، وضمان الجودة (اشتقاق حالات الاختبار لكل حالة وكل تدفق).

## 1.2 كيف تُقرأ الوثيقة

- `SC-XX` معرف شاشة، `FL-XX` معرف تدفق، `R-XX` قاعدة جوهرية (SRS §1.6)، `FR-XXX-NNN` متطلب وظيفي (SRS §4)، `US-XXX-NNN` قصة مستخدم، `Master §NN` قسم المرجع الحاكم.
- كل شاشة موصوفة بستة حقول إلزامية: **الغرض / الوصول / العناصر / الحالات الإلزامية / الربط الوظيفي / ملاحظات UX-RTL**.
- **الربط العمودي إلزامي**: كل شاشة تحمل FR + مجموعة API + قصة US. لم تُكتب وثيقة `API_ENDPOINTS.md` بعد، لذا تُستخدم أسماء المجموعات المنطقية التالية (تُستبدل بأسماء المسارات النهائية عند اعتماد وثيقة API دون تغيير السلوك):

| الرمز | المجموعة المنطقية | الرمز | المجموعة المنطقية |
|---|---|---|---|
| `EP-BOOT` | Bootstrap (الإصدار/الحالة/الإعدادات/الخدمات المفعلة) | `EP-SAV` | Savings (الحصالة) |
| `EP-AUTH` | Auth (OTP/PIN/الجلسات/الأجهزة/البصمة) | `EP-TRX` | Transactions (السجل/التفاصيل/الكشف) |

## 1.3 قاعدة الشاشة المالية (SRS §7.2 / Master §85)

> **لا شاشة شكلية بلا State وAPI.** كل شاشة في هذه الوثيقة مربوطة بحالاتها الإلزامية وبمجموعة API فعلية.

ضوابط مشتقة تُطبق على أي شاشة جديدة قبل قبولها في الكتالوج:

1. تحدد حالتها لكل عنصر من عناصر قائمة §3.1 (حيث ينطبق) — يُمنع تصميم حالة النجاح فقط (Master §95).
2. تحدد سلوكها تحت الحالات العالمية الثماني (§3.2) — لا أخطاء مختلفة لكل شاشة (Master §110).
3. بياناتها المالية من الخادم حصراً (R-01)؛ لا يُعرض رصيد أو نتيجة محسوبة محلياً.
4. أزرارها المالية معطلة مع رسالة واضحة عند Offline (R-02) وتُعاد تفعيلها عند العودة.
5. أي عملية حساسة تمر بشاشة تأكيد PIN (SC-13) وتحمل مفتاح Idempotency (FR-LDG-004).

# 3. الحالات الإلزامية والحالات العالمية

## 3.1 الحالات الإلزامية لكل شاشة مالية (SRS §7.3 + Master §95)

قائمة SRS §7.3 هي المرجع: عشر حالات من Master §95 (Initial, Loading, Success, Empty, Error, Pending, Unauthorized, Offline, Maintenance, Restricted) مضافاً إليها `OutOfServiceArea` و`ForceUpdate` من SRS §7.3 (بمجموع 12 حالة موحدة). كل شاشة مالية تُصمَّم للحالات التي تنطبق عليها من هذا الجدول — **يُمنع تصميم Success فقط**:

| # | الحالة | متى تظهر | الشكل الموحد | الإجراء المطلوب |
|---|---|---|---|---|
| 1 | Initial | قبل أول استدعاء API | هيكل الشاشة بقيم فارغة موجَّهة (placeholders) | استدعاء البيانات تلقائياً |
| 2 | Loading | أثناء الجلب/التنفيذ | Skeletons بنفس شكل العناصر النهائية (SRS §7.4) | — (لا أزرار مالية نشطة) |
| 3 | Success | نجاح الاستدعاء/العملية | البيانات الفعلية من الخادم | إجراءات الشاشة الطبيعية |
| 4 | Empty | استجابة فارغة | `EmptyState` (§2.2 #9) | زر إنشاء/إعادة محاولة حسب السياق |
| 5 | Error | فشل الاستدعاء (شبكة/خادم/تحقق) | `ErrorState` (§2.2 #10) برسالة الخادم المفهومة | إعادة المحاولة + الدعم |
| 6 | Pending | عملية قيد المعالجة خادمياً | `StatusChip` كهرماني + سبب المعلقية + عمر العملية | "تحديث الحالة" — استعلام نفس العملية (§114) |
| 7 | Unauthorized | 401 / جلسة غير صالحة | إعادة مصادقة شفافة | SC-03 ثم استئناف الشاشة نفسها |
| 8 | Offline | لا اتصال | بانر عالمي + تعطيل كل زر مالي (R-02) | عرض آخر لقطة موسومة "بيانات قديمة" (FR-OFF-001) |
| 9 | Maintenance | حالة النظام صيانة (Master §51) | شاشة عالمية من `EP-BOOT` | انتظار أو الدعم |
| 10 | Restricted | حساب RESTRICTED أو خدمة مقيدة | بانر تقييد يحدد المسموح | عرض الوظائف المسموحة فقط |
| 11 | OutOfServiceArea | خارج نطاق الخدمة (FR-GEO) | شاشة نطاق + خريطة النطاق | تواصل مع الدعم |
| 12 | ForceUpdate | إصدار أقدم من الأدنى (Master §52) | نافذة غير قابلة للإغلاق | تحديث من المتجر |

## 3.2 خريطة الحالات العالمية الثماني (Master §110) — سلوك موحّد

> كل التطبيق يفهم هذه الحالات الثماني **مرة واحدة** (طبقة Global State موحدة) بدل أخطاء مختلفة في كل شاشة:

| الحالة العالمية | السلوك الموحد (شاشة/بانر/نافذة) | آلية الاكتشاف |
|---|---|---|
| No Internet | بانر علوي ثابت "لا يوجد اتصال" + تعطيل الأزرار المالية + آخر لقطة بوسم "بيانات قديمة" | مراقب الاتصال + فشل الطلبات |
| Server Down | شاشة `ErrorState` عامة "الخدمة متوقفة مؤقتاً" + إعادة محاولة تلقائية محدودة | استجابات 5xx متكررة (3 متتالية) |
| Maintenance | شاشة صيانة كاملة بنص ومدة متوقعة من الإدارة | `system_state` من `EP-BOOT` |
| Force Update | نافذة عالمية غير قابلة للإغلاق + زر المتجر | مقارنة الإصدار بـ `min_version` من `EP-BOOT` |
| Account Frozen | شاشة "الحساب مجمّد" (Restricted UI — Master §145): عرض السجل للقراءة فقط + مسار دعم مباشر (SC-43/SC-46) + زر WhatsApp | رد 403 بحالة FROZEN من أي مجموعة API |
| Region Restricted | شاشة خارج نطاق الخدمة + خريطة المحافظات الثماني + قناة الدعم | فحص الأهلية من `EP-GEO` عند الجذور وDeep Link |
| Service Disabled | إخفاء الخدمة من كتالوج SC-09 أو وسم "متوقفة مؤقتاً" (لا حذف مفاجئ) | Feature Flags من `EP-BOOT` (Master §50) |
| Session Expired | إعادة مصادقة شفافة: SC-03 ثم العودة لنفس الشاشة والمهمة دون فقدان السياق | 401 + فشل تجديد الجلسة (FR-AUTH-023) |

# 4. خريطة التنقل (Navigation)

## 4.1 الهيكل العام

```text
                      ┌──────────────────────────────────────────────┐
                      │  SC-01 Splash (RootGate)                     │
                      │  EP-BOOT: الإصدار + حالة النظام + الإعدادات  │
                      └────────────────────────┬─────────────────────┘
                                               │
        ┌──────────────────────────────────────┼───────────────────────────────────┐
        │                                      │                                   │
   ForceUpdate / Maintenance            لا جلسة مسجلة                        جلسة صالحة
   (شاشة عالمية §3.2)                          │                                   │
        │                                SC-02 Onboarding                     SC-03 قفل الدخول
        │                                      │                              (PIN / بصمة)
        │                        SC-05 تسجيل جديد ← SC-04 OTP                      │
        │                                      │                                   │
        └────────────────────────── كلاهما يصل ────────────────────────────────────┘
                                               │
                          ┌────────────────────┴─────────────────────┐
                          │  AppShell — Bottom Navigation (5 تابات)  │
                          │ [الرئيسية] [الخدمات] [السجل] [الدعم] [ملفي]
                          └──────────────────────────────────────────┘
```

- **RTL من البداية** (Master §92): شريط التنقل السفلي يبدأ من اليمين بترتيب (الرئيسية، الخدمات، السجل، الدعم، ملفي)؛ أيقونة الرجوع تشير يميناً؛ الأدراج والشرائح تفتح من اليمين.
- **وضعا الوكيل/التاجر** لا يغيّران هيكل القشرة: تبديل الدور من الملف الشخصي (SC-38) يعيد بناء التابات إلى قشرة الوكيل (طابور/تسوية/عمولاتي/الدعم/ملفي) أو قشرة التاجر (دفع/مدفوعاتي/تسوياتي/تقاريري/ملفي) بعد تحقق الصلاحية من الخادم (`EP-AGT`/`EP-MRC`).

# 6. المجموعات الأربع عشرة — الكتالوج الكامل

## 6.1 مجموعة البداية (Onboarding & Auth) — SC-01..SC-07

### SC-01 — شاشة البداية (Splash)

| البند | المواصفة |
|---|---|
| **الغرض** | بوابة الجذر: فحص الإصدار وحالة النظام والجلسة قبل تحديد وجهة الإقلاع (Master §7/§8) |
| **الوصول** | إقلاع التطبيق (بارد/ساخن) |
| **العناصر** | شعار النجمة الثمانية بحركة "S" خفيفة، اسم المنتج، مؤشر تقدم رفيع ذهبي، استدعاء `EP-BOOT` (الإصدار الأدنى، حالة النظام، Feature Flags، إعدادات الإقلاع) |
| **الحالات الإلزامية** | Loading (فحص)، ForceUpdate (نافذة عالمية)، Maintenance (شاشة عالمية)، Offline (يُسمح بالتوجه للشاشات غير المالية مع وسم بيانات قديمة)، Error (خادم غير مستجيب → شاشة Server Down) |
| **الربط الوظيفي** | FR-AUTH-010 + EP-BOOT + Master §51/§52 |
| **ملاحظات UX/RTL** | مدة قصوى 3 ثوانٍ ثم قرار؛ لا تعرض أي أرصدة أو بيانات شخصية؛ نجاح الفحص لا يعني جلسة صالحة (فحص منفصل) |

### SC-02 — التعريف (Onboarding)

| البند | المواصفة |
|---|---|
| **الغرض** | تعريف المستخدم الجديد بالمنتج قبل التسجيل + اختيار اللغة الأولى |
| **الوصول** | من SC-01 عند غياب الجلسة وغياب علم "تم العرض" |
| **العناصر** | 4 شرائح: (1) محفظة متعددة العملات YER/SAR/USD (2) الحوالات والوكيل ورمز التسليم (3) الدفع والخدمات (شحن/فواتير/حصالة) (4) الأمان (PIN/بصمة/OTP)؛ مؤشر شرائح، زر تخطٍّ، اختيار اللغة ع/EN أعلى الشاشة |
| **الحالات الإلزامية** | Success فقط (محتوى ثابت) — لا حالة مالية |
| **الربط الوظيفي** | FR-ACC-002 (اللغة) + Master §93 + EP-BOOT (نصوص الشرائح قابلة للتحديث) |
| **ملاحظات UX/RTL** | السحب بين الشرائح يتبع اتجاه RTL؛ الشريحة الأولى هي نقطة اختيار اللغة قبل أي نص |

### SC-03 — تسجيل الدخول (Login / App Lock)

| البند | المواصفة |
|---|---|
| **الغرض** | إثبات هوية المستخدم العائد (PIN أو بصمة) وفتح الجلسة، أو مسار نسيان PIN |
| **الوصول** | من SC-01 (جلسة موجودة لكن مقفلة) أو بعد Session Expired أو بعد تسجيل الخروج |
| **العناصر** | رقم الهاتف (معروض للجلسة المحفوظة)، إدخال PIN عبر `PINPad`، زر بصمة (إن مفعلة على جهاز موثوق)، رابط "نسيت PIN؟" (→ OTP + تحقق إضافي)، رابط تبديل الحساب (→ SC-05) |
| **الحالات الإلزامية** | Error (3 محاولات → تأخير تصاعدي، 5 → قفل مؤقت + تنبيه أمني — FR-AUTH-017)، Frozen (شاشة حساب مجمّد مع مسار دعم — Master §145)، Maintenance/ForceUpdate (عالمية)، Offline (الدخول غير ممكن — الجلسة خادمية) |
| **الربط الوظيفي** | FR-AUTH-008/009/010/011/012/018 + EP-AUTH (session) + US-CUST-003 |
| **ملاحظات UX/RTL** | تسلسل الفحص الثابت قبل أي إدخال: إصدار → حالة النظام → فحص أمني → جلسة → PIN (Master §8)؛ جهاز جديد يضيف خطوة OTP + تنبيه أمني فوري |

### SC-04 — رمز التحقق (OTP)

| البند | المواصفة |
|---|---|
| **الغرض** | تحقق رقم الهاتف بالـOTP (تسجيل/جهاز جديد/استعادة/عمليات 2FA) |
| **الوصول** | من SC-05، من SC-03 (جهاز جديد/نسيت PIN)، ومن العمليات الحساسة عند تفعيل 2FA |
| **العناصر** | `OTPInput` بـ6 خانات، رقم الهاتف المرسل إليه، مؤقت إعادة الإرسال (60ث — FR-AUTH-002)، زر إعادة إرسال، عدّاد المحاولات المتبقية (5 ثم قفل 15 دقيقة) |
| **الحالات الإلزامية** | Loading (تحقق)، Error (رمز خاطئ)، Pending (قفل مؤقت بعد استنفاد المحاولات)، Error (استنفاد حد الإرسال اليومي) |
| **الربط الوظيفي** | FR-AUTH-001/002/003/012 + FR-AUTH-013 + EP-AUTH (otp/verify) + US-CUST-001 |
| **ملاحظات UX/RTL** | الخانات تُملأ من اليمين لليسار؛ التنقل التلقائي بين الخانات؛ لصق الرمز كاملاً مدعوم |

### SC-05 — تسجيل جديد (Create Account)

| البند | المواصفة |
|---|---|
| **الغرض** | إدخال البيانات الأساسية والمنطقة والموافقة على الشروط وفحص الأهلية وإنشاء الحساب |
| **الوصول** | من SC-02 أو رابط "حساب جديد" في SC-03 (بعد OTP ناجح) |
| **العناصر** | حقل الاسم الكامل، اختيار المحافظة/المنطقة (من `EP-GEO` — المحافظات الثماني)، مربعا موافقة صريحان (الشروط + الخصوصية — FR-AUTH-006)، زر إنشاء الحساب، رابط "الرقم مستخدم مسبقاً؟ استعادة عبر الدعم" |
| **الحالات الإلزامية** | Loading (إنشاء)، Error (رقم مستخدم — FR-AUTH-003)، OutOfServiceArea/Restricted (فشل الأهلية — FR-GEO-003)، Offline (منع الإنشاء) |
| **الربط الوظيفي** | FR-AUTH-003/004/005/006/007 + FR-GEO-003 + EP-AUTH (register) + EP-GEO + US-CUST-001 |
| **ملاحظات UX/RTL** | التسجيل لا يكتمل بنجاح OTP وحده (Master §7): البيانات + المنطقة + الشروط + PIN + الجهاز كلها قبل الوصول للرئيسية؛ المحافظات قائمة من الخادم لا ثابتة محلياً |

### SC-06 — إنشاء رمز PIN (Create PIN)

| البند | المواصفة |
|---|---|
| **الغرض** | تعيين PIN من 6 خانات للمستخدم الجديد أو بعد إعادة التعيين |
| **الوصول** | خطوة إلزامية بعد SC-05؛ أو من مسار "نسيت PIN" في SC-03 |
| **العناصر** | `PINPad`، حقل نقاط، إدخال ثم تأكيد (إعادة الإدخال)، مؤشر تطابق، تحذير الأنماط الضعيفة (تكرارات/تسلسل) |
| **الحالات الإلزامية** | Error (عدم تطابق)، Error (نمط ضعيف)، Loading (حفظ خادمي) |
| **الربط الوظيفي** | FR-AUTH-015/019 + EP-AUTH (pin) + US-CUST-001 |
| **ملاحظات UX/RTL** | لا يُخزَّن PIN محلياً ولا يُرسل كنص صريح (R-07)؛ التخزين مشفر في الخادم فقط (FR-AUTH-015) |

### SC-07 — تفعيل البصمة (Biometric Activation)

| البند | المواصفة |
|---|---|
| **الغرض** | عرض تفعيل البصمة/Face ID كمسار دخول وعمليات بديل عن PIN |
| **الوصول** | خطوة اختيارية بعد SC-06 (أول مرة) أو من SC-40 الأمان |
| **العناصر** | توضيح متى تُستخدم البصمة (الدخول + العمليات الحساسة)، زر تفعيل يستدعي واجهة النظام، ملاحظة السقوط إلى PIN، زر "لاحقاً" |
| **الحالات الإلزامية** | Error (فشل القياس الحيوي)، Success (مفعّلة) |
| **الربط الوظيفي** | FR-AUTH-018 + EP-AUTH (biometric) + EP-ACC + US-CUST-003 |
| **ملاحظات UX/RTL** | البصمة مسار راحة لا بديل أمني: الفشل ثلاث مرات يسقط تلقائياً إلى PIN؛ الحساسية تبقى خادمية |

## 6.2 مجموعة الرئيسية (Home) — SC-08..SC-10

### SC-08 — الرئيسية (Home)

| **الربط الوظيفي** | FR-WLT-002/005/007/008 + EP-WLT + EP-TRX + US-CUST-004 |

### SC-11 — التحويل (Transfer)

| البند | المواصفة |

| **الغرض** | إدخال بيانات التحويل لمشترك: المستفيد والعملة والمبلغ والحصول على quote الرسوم |
| **الوصول** | الرئيسية → زر تحويل / من مفضّل / من إشعار / من QR شخصي |
| **العناصر** | حقل رقم الهاتف أو الاختيار من المفضلين (شريط أفقي بصور/أسماء مستعارة) أو مسح QR شخصي، بطاقة المستفيد (الاسم مُخفى جزئياً "أح*** م" — Master §19/FR-TRF-001)، `CurrencyTabs`، `AmountPad` للمبلغ، سطر الرسوم المتوقعة من quote، حقل ملاحظة اختيارية (FR-TRF-006)، زر متابعة |
| **الحالات الإلزامية** | Loading (quote)، Error (شبكة/خدمة/مستفيد غير موجود)، Offline (منع المتابعة — R-02)، Restricted (منطقة)، Frozen |
| **الربط الوظيفي** | FR-TRF-001/002/006 + FR-FAV-001/003 + EP-TRF (quote) + EP-FAV + US-CUST-005 |
| **ملاحظات UX/RTL** | لوحة أرقام معكوسة الترتيب منطقياً للعربية؛ عرض الرسوم قبل المتابعة دائماً؛ تأكيد PIN في الخطوة التالية؛ الحد الأدنى/الأقصى للمبلغ يظهر تحت الحقل من محرك الحدود (FR-LDG-012) |

### SC-12 — مراجعة التحويل (Transfer Review)

| البند | المواصفة |
|---|---|
| **الغرض** | عرض الوضوح المالي الكامل قبل التنفيذ: المبلغ + الرسوم + الإجمالي + المستفيد + العملة |
| **الوصول** | زر متابعة من SC-11 |
| **العناصر** | بطاقة مراجعة (ReceiptCard بنمط معاينة): المستفيد المقنّع، العملة، المبلغ، الرسوم، الإجمالي المخصوم، صلاحية الـquote (عدّاد قصير — تثبيت لحظي FR-WLT-006)، ملاحظة التحويل، زر "تأكيد وتحويل" (يولّد مفتاح Idempotency — FR-LDG-004)، رابط تعديل |
| **الحالات الإلزامية** | Error (انتهت صلاحية الـquote → العودة لـ SC-11)، Offline (منع التأكيد)، Restricted/Frozen، Loading (تنفيذ يبدأ بعد PIN) |
| **الربط الوظيفي** | FR-TRF-003 + FR-LDG-004/011 + EP-TRF (execute) + US-CUST-005 |
| **ملاحظات UX/RTL** | "لا مفاجآت" (SRS §7.4): الإجمالي المخصوم هو الرقم الأبرز (`type.display`)؛ انتهاء العدّاد يلغي التأكيد ولا يجدد الرسوم صامتاً |

### SC-13 — تأكيد PIN للعمليات الحساسة (PIN Confirmation — مشتركة)

| البند | المواصفة |
|---|---|
| **الغرض** | إثبات نية المستخدم قبل تنفيذ أي عملية حساسة (تحويل/سحب/دفع/شراء كروت/تغييرات حساسة/إضافة جهاز/تغيير PIN) |
| **الوصول** | تُستدعى كخطوة من: SC-12، SC-20، SC-23، SC-27/28/29، SC-15/32، SC-40/41 — ليست تاباً |
| **العناصر** | عنوان يحدد العملية الجارية ("تأكيد تحويل 500 ريال")، `PINPad`، زر بصمة إن مفعلة، عدّاد المحاولات والتأخير التصاعدي |
| **الحالات الإلزامية** | Error (PIN خاطئ — 3 تأخير/5 قفل مؤقت + تنبيه أمني — FR-AUTH-017)، Frozen (تجميد العمليات وطلب الدعم عند بلوغ حد السياسة)، Loading (تحقق خادمي) |
| **الربط الوظيفي** | FR-AUTH-016/017/018 + EP-AUTH (verify) + كل مجموعات العمليات (TRF/CASH/PAY/TOP/BIL/SAV) |
| **ملاحظات UX/RTL** | شاشة مشتركة واحدة لا نُسخ لكل عملية؛ نجاحها لا يساوي نجاح العملية — النتيجة تأتي من الخادم (Master §86) |

### SC-14 — نتيجة العملية/الإيصال (Transfer Result & Receipt)

| البند | المواصفة |
|---|---|
| **الغرض** | عرض النتيجة النهائية **من الخادم حصراً** مع إيصال قابل للمشاركة |
| **الوصول** | بعد تنفيذ أي عملية (تحويل/دفع/شحن/فاتورة/كروت) عبر SC-13 |
| **العناصر** | علامة الحالة (نجاح/فشل/معلق) بلون الحالة، `ReceiptCard`: المرجع `SW-YYYYMMDD-XXXXXXXX`، التاريخ والوقت، النوع، الطرفان، العملة، المبلغ/الرسوم/الإجمالي، QR تحقق، أزرار: مشاركة، إضافة مفضّل (بعد التحويل — FR-FAV-002)، "الإبلاغ عن مشكلة" (→ SC-44 مرتبطة)، زر "تم" → الرئيسية |
| **الحالات الإلزامية** | Success، Pending ("قيد التنفيذ — بانتظار نتيجة الخادم/المزود" + زر تحديث الحالة)، Error (السبب من الخادم + إجراء)، Offline (استعلام العملية الأصلية عند العودة — Master §114) |
| **الربط الوظيفي** | FR-LDG-005/009 + FR-TRF-005 + FR-FAV-002 + EP-TRF/EP-PAY/EP-TOP (status) + US-CUST-005/US-CUST-015 |
| **ملاحظات UX/RTL** | لا يُعرض "نجاح" اعتماداً على نجاح التنقل (Master §86)؛ الإيصال لا يحتوي PIN أبداً (Master §60)؛ العودة للرئيسية تعيد الجلب من الخادم (§87) |

### SC-15 — التحويل بين محافظي (Transfer Between My Wallets)

| البند | المواصفة |
|---|---|
| **الغرض** | تحويل بين محافظ المستخدم نفسه بعملات مختلفة عبر محرك FX الداخلي |
| **الوصول** | من SC-10 (تفاصيل محفظة) أو من SC-11 (تبويب "بين محافظي") |
| **العناصر** | اختيار "من عملة" و"إلى عملة" (`CurrencyTabs` مزدوجة)، `AmountPad`، بطاقة سعر الصرف اللحظي المثبَّت + الرسوم (إن وُجدت)، بطاقة "ستستلم" بالمبلغ المحوَّل، مراجعة → SC-13 → SC-14 |
| **الحالات الإلزامية** | Loading (سعر الصرف — FR-WLT-006)، Error (رصيد غير كافٍ/سعر منتهٍ)، Offline (منع المتابعة)، Restricted |
| **الربط الوظيفي** | FR-TRF-008 + FR-WLT-005/006 + EP-TRF (fx-quote/execute) + US-CUST-006 |
| **ملاحظات UX/RTL** | السعر يثبَّت لحظة التنفيذ داخل المعاملة (FR-WLT-006) — العرض بقيمة استرشادية بصلاحية قصيرة؛ السهم بين المحفظتين يتبع RTL |

## 6.4 مجموعة الحوالات (Remittances) — SC-16..SC-18

### SC-16 — إنشاء حوالة (Create Remittance)

| البند | المواصفة |
|---|---|
| **الغرض** | إرسال مبلغ لمستلم **غير مشترك** يُسلَّم نقداً عبر وكيل، مع رمز تسليم يعمل مرة واحدة |
| **الوصول** | الخدمات → الحوالات / الرئيسية (اختصار ضمن الخدمات) |
| **العناصر** | المبلغ + `CurrencyTabs`، بيانات المستلم (الاسم الكامل + رقم الهاتف — لإشعار SMS)، اختيار المدينة/الوكيل المقترح (بحث أو من SC-25)، بطاقة الرسوم + عمولة الوكيل (FR-REM-007)، مراجعة → SC-13 → إنشاء → عرض رمز التسليم |
| **الحالات الإلزامية** | Loading (quote/إنشاء)، Error (حدود/رصيد)، Offline (منع المتابعة)، Restricted، Empty (لا وكلاء في المدينة المختارة) |
| **الربط الوظيفي** | FR-REM-001/002/007 + EP-REM (create) + EP-CASH (اقتراح الوكيل) + US-CUST-007 |
| **ملاحظات UX/RTL** | توضيح صريح للمستخدم: "المبلغ يُخصم الآن ويُسلَّم للمستلم عند الوكيل بالرمز"؛ إشعار SMS للمستلم عند الإنشاء (FR-REM-004) |

### SC-17 — تتبع الحوالة (Track Remittance)

| البند | المواصفة |
|---|---|
| **الغرض** | متابعة حالة حوالة حية + عرض رمز التسليم وإدارته |
| **الوصول** | من SC-14 بعد الإنشاء / من السجل SC-34 / من إشعار Deep Link `southwallet://remittance/{id}` |
| **العناصر** | مسار زمني (timeline) بالحالات (قيد التسليم → مُسلَّمة / منتهية / ملغاة — FR-REM-004)، بطاقة رمز التسليم (رقمي + QR) مع صلاحية زمنية ومؤقت، زر مشاركة الرمز مع المستلم، زر "إلغاء الحوالة" (فقط قبل التسليم — FR-REM-005)، بيانات الوكيل/المدينة |
| **الحالات الإلزامية** | Loading، Success، Pending (قيد التسليم)، Error، Offline (لقطة موسومة + منع الإلغاء Offline)، Empty |
| **الربط الوظيفي** | FR-REM-002/004/005/008 + EP-REM (status/cancel) + US-CUST-007 |
| **ملاحظات UX/RTL** | الإلغاء يسترد المبلغ للمحفظة عبر Reversal (FR-REM-005) ويُعرض في السجل كعملية مرتبطة بالأصل؛ انتهاء الصلاحية يعرض "منتهية — استُرد المبلغ تلقائياً" (FR-REM-008) |

### SC-18 — استلام حوالة (Receive Remittance)

| البند | المواصفة |
|---|---|
| **الغرض** | عرض الحوالات الواردة إلى محفظتي (من شبكات الصرافة المتكاملة) وقبولها/متابعتها |
| **الوصول** | الخدمات → الحوالات → تبويب "واردة" / من إشعار حوالة واردة |
| **العناصر** | قائمة الحوالات الواردة (المرسل الخارجي، المبلغ، العملة، الحالة)، تفصيل حوالة (المرجع الخارجي + الدفع للمحفظة مباشرة)، تنبيهات الحالة |
| **الحالات الإلزامية** | Loading، Success، Empty (`EmptyState` — لا حوالات واردة)، Error، Offline |
| **الربط الوظيفي** | FR-REM-006 (Should — عبر Adapter بشبكات الصرافة) + EP-REM (inbox) + US-CUST-008 |
| **ملاحظات UX/RTL** | دفع الحوالة للمحفظة مباشرة مع إشعار فوري؛ الميزة مشروطة بعقد تكامل الشبكة (A-03) — إن لم تُفعّل تظهر رسالة "القناة غير متاحة حالياً" بدل شاشة فارغة صامتة |

## 6.5 مجموعة الدفع (Payments) — SC-19..SC-21

### SC-19 — مسح QR (Scan QR)

| البند | المواصفة |
|---|---|
| **الغرض** | قراءة QR تاجر/نقطة بيع وإرسال حمولته للخادم للحل والتحقق — لا ثقة محلية |
| **الوصول** | الرئيسية → زر دفع → مسح / من قلب شاشة التاجر SC-53 |
| **العناصر** | عدسة كاميرا بإطار نجمة ثمانية، دليل محاذاة، مصباح، رسائل رفض واضحة، (مسح QR شخصي من SC-11 يستخدم نفس المكون بوضع آخر) |
| **الحالات الإلزامية** | Error (QR غير موقّع/منتهٍ/جهة غير قابلة للتحقق → رفض صريح — FR-PAY-007)، Error (صلاحية كاميرا مرفوضة)، Loading (حل خادمي)، Offline (منع المسح المالي) |
| **الربط الوظيفي** | FR-PAY-001/007 + EP-PAY (resolve) + US-CUST-009 |
| **ملاحظات UX/RTL** | التطبيق لا يفكّ التوقيع محلياً: الحمولة (merchant_id, terminal_id, العملة, المبلغ الثابت, مرجع, إصدار, توقيع) ترسل كما هي إلى الخادم (R-10) |

### SC-20 — مراجعة الدفع/دفع التاجر (Pay Review / Merchant Payment)

| البند | المواصفة |
|---|---|
| **الغرض** | حل التاجر وعرضه مع المبلغ والرسوم قبل تأكيد الدفع (QR أو POSCOF أو Pay Request) |
| **الوصول** | بعد SC-19، أو الدخول المباشر بتبويب "رقم نقطة البيع POSCOF"، أو من Deep Link Pay Request |
| **العناصر** | بطاقة التاجر (الاسم + الفرع + نقطة البيع من حلّ الخادم)، `CurrencyTabs`، المبلغ (معبأ إن كان ثابتاً في QR وإلا `AmountPad`)، سطر الرسوم من quote، زر تأكيد الدفع → SC-13 → SC-14 |
| **الحالات الإلزامية** | Loading (حل/quote)، Error (POSCOF غير موجود/معطل — FR-PAY-002)، Error (رصيد/حدود)، Offline (منع التأكيد)، Restricted، Frozen |
| **الربط الوظيفي** | FR-PAY-002/003/007 + EP-PAY (resolve/quote/execute) + US-CUST-009 |
| **ملاحظات UX/RTL** | اسم التاجر يُعرض قبل التأكيد إلزامياً (FR-PAY-002)؛ لا دفع لجهة لم يستطع الخادم التحقق منها (Master §24) |

### SC-21 — طلب دفع — وضع التاجر (Pay Request)

| البند | المواصفة |
|---|---|
| **الغرض** | التاجر يرسل طلب دفع مباشراً لعميل حاضر فينفتح لدى العميل على شاشة المراجعة مباشرة |
| **الوصول** | وضع التاجر (SC-53) → "طلب دفع"؛ لدى العميل: إشعار Pay Request → Deep Link |
| **العناصر** | (جانب التاجر) إدخال المبلغ + العملة + إرسال Push + حالة الطلب (بانتظار/مقبول/مرفوض/منتهي الصلاحية)؛ (جانب العميل) يصل SC-20 معبأ بالطلب مع زر قبول/رفض |
| **الحالات الإلزامية** | Pending (بانتظار قبول العميل)، Success، Error (انتهاء صلاحية الطلب)، Offline |
| **الربط الوظيفي** | FR-PAY-004 (Should) + EP-MRC (pay-request) + EP-PAY + US-MRC-005 |
| **ملاحظات UX/RTL** | الطلب قناة توجيه فقط: الدفع يمر بنفس تحقق الخادم الكامل وPIN (لا دفع بضغطة إشعار واحدة) |

## 6.6 مجموعة السحب/الإيداع (Cash In/Out) — SC-22..SC-26

### SC-22 — طلب إيداع (Deposit Request)

| البند | المواصفة |
|---|---|
| **الغرض** | إنشاء طلب إيداع نقدي عبر وكيل يُأكّده الوكيل بعد استلام النقد |
| **الوصول** | الرئيسية → زر إيداع / الخدمات → السحب والإيداع |
| **العناصر** | المبلغ + `CurrencyTabs`، اختيار الوكيل (من SC-25 أو بحث)، الرسوم المتوقعة، زر إنشاء الطلب، بطاقة حالة الطلب (PENDING — "اذهب للوكيل خلال المهلة" + العدّاد) |
| **الحالات الإلزامية** | Loading، Pending (بانتظار تأكيد الوكيل)، Success، Error (حدود — FR-CWD-005)، Error (رفض الوكيل مع السبب — FR-CWD-006)، Offline (منع الإنشاء) |
| **الربط الوظيفي** | FR-CWD-001/005/006 + EP-CASH (deposit-request) + US-CUST-012 |
| **ملاحظات UX/RTL** | لا يُضاف الرصيد قبل تأكيد الوكيل والتحقق الخادمي (Master §21)؛ انتهاء المهلة → EXPIED وطلب جديد |

### SC-23 — طلب سحب (Withdraw Request)

| البند | المواصفة |
|---|---|
| **الغرض** | إنشاء طلب سحب نقدي عبر وكيل: خصم Hold (تجميد) + توليد رمز سحب |
| **الوصول** | الرئيسية → زر سحب / الخدمات → السحب والإيداع |
| **العناصر** | المبلغ + `CurrencyTabs`، اختيار الوكيل (من SC-25)، بطاقة الرسوم والحدود الدنيا/العليا (FR-CWD-005)، مراجعة → SC-13 → Hold → عرض رمز السحب (ينتقل إلى SC-24) |
| **الحالات الإلزامية** | Loading، Error (رصيد غير كافٍ/حدود)، Offline (منع السحب — R-02)، Restricted، Frozen |
| **الربط الوظيفي** | FR-CWD-002/003/005 + FR-WLT-008 + EP-CASH (withdraw-request) + US-CUST-013 |
| **ملاحظات UX/RTL** | يُعرض للمستخدم بوضوح: "المبلغ مجمّد (Hold) حتى التسليم أو انتهاء المهلة" — لا يختفي من الرصيد بصمت (FR-WLT-008) |

### SC-24 — رمز السحب (Withdraw Code)

| البند | المواصفة |
|---|---|
| **الغرض** | عرض رمز السحب (رقمي + QR) ومتابعة حالة السحب حتى الإتمام |
| **الوصول** | بعد إنشاء طلب السحب / من السجل / من إشعار |
| **العناصر** | رمز رقمي كبير + QR للوكيل، صلاحية زمنية بمؤقت تنازلي، حالة السحب الحية (READY_FOR_COLLECTION → COLLECTED → COMPLETED — Master §23)، زر "إلغاء السحب" قبل القبض، بيانات الوكيل |
| **الحالات الإلزامية** | Pending (جاهز للقبض)، Success (مكتمل — إيصال)، Error (EXPIRED → تحرير Hold تلقائياً + إشعار — FR-CWD-003)، Offline (عرض الرمز محلياً مسموح — التحقق عند الوكيل خادمي) |
| **الربط الوظيفي** | FR-CWD-002/003 + EP-CASH (withdraw-status/cancel) + US-CUST-013 |
| **ملاحظات UX/RTL** | الإلغاء أو انتهاء المهلة يحرّر المبلغ المجمّد عبر Reversal (FR-CWD-003) ويظهر في السجل؛ عرض الرمز Offline مقبول لأن التنفيذ الفعلي خادمي عند الوكيل |

### SC-25 — خريطة الوكلاء (Agents Map)

| البند | المواصفة |
|---|---|
| **الغرض** | إيجاد أقرب وكيل/نقطة خدمة نشط لتنفيذ إيداع أو سحب أو تسليم |
| **الوصول** | من SC-22/SC-23 (اختيار الوكيل) / الخدمات → خريطة الوكلاء |
| **العناصر** | خريطة (Google Maps/Mapbox — SRS §8) بموقع المستخدم، دبابيس الوكلاء النشطين (لون الحالة)، قائمة مرتبة بالأقرب (الاسم/المسافة/ساعات العمل/الحالة — FR-CWD-004)، فلتر المحافظة/المدينة، بحث بالاسم |
| **الحالات الإلزامية** | Loading، Success، Empty (لا وكلاء قريبين)، Error (صلاحية الموقع مرفوضة → قائمة بدون مسافات)، Offline (آخر لقطة موسومة "بيانات قديمة")، OutOfServiceArea |
| **الربط الوظيفي** | FR-CWD-004 + EP-CASH (agents) + EP-GEO + US-CUST-012 |
| **ملاحظات UX/RTL** | GPS ليس حكماً للأهلية (R-06) — يستخدم للترتيب والعرض فقط؛ النتائج من الخادم |

### SC-26 — تفاصيل وكيل (Agent Details)

| البند | المواصفة |
|---|---|
| **الغرض** | عرض بيانات وكيل قبل التوجه إليه وبدء طلب عنده |

| **ملاحظات UX/RTL** | قرار موثّق: تغطية بند Master §85 تتحقق بهيكل مُعرّف مخفي؛ ظهورها في الكتالوج (SC-09) لا يحدث إلا بعلم Feature Flag صريح من الإدارة |

# 7. التدفقات الرئيسية (User Flows) — FL-01..FL-15

> كل تدفق بصيغة خطوات مرقمة داخل كتلة، والفروع بصيغة (شرط → فرع). الرموز: SC شاشة، EP مجموعة API، FR متطلب، R قاعدة، Master §NN قسم المرجع الحاكم.

## FL-01 — التسجيل الكامل (من Splash إلى الرئيسية)

```text
1. إقلاع التطبيق → SC-01: استدعاء EP-BOOT (الإصدار + حالة النظام + الإعدادات)
   ↓
2. فحص الإصدار
   ─ فرع: إصدار أقدم → ForceUpdate → نافذة عالمية → متجر التطبيقات (نهاية)
   ─ فرع: صيانة → شاشة صيانة عالمية (نهاية)
   ↓
3. لا جلسة وأول استخدام → SC-02 Onboarding (اختيار اللغة ع/EN ثم 4 شرائح)
   ↓
4. "إنشاء حساب" → SC-05: إدخال رقم الهاتف → إرسال OTP (EP-AUTH)
   ─ فرع: الرقم مستخدم مسبقاً → خيار "استعادة الحساب" عبر الدعم (FR-AUTH-003)
   ↓
5. SC-04 OTP (6 خانات، صلاحية 5 دقائق)
   ─ فرع: OTP خاطئ → رسالة + تنقيص عدّاد المحاولات (5 محاولات ثم قفل 15 دقيقة — FR-AUTH-001)
   ─ فرع: انتهاء المهلة → إعادة إرسال بعد 60ث بحد يومي (FR-AUTH-002)
   ↓
6. البيانات الأساسية: الاسم + اختيار المحافظة/المنطقة (EP-GEO)
   ─ فرع: خارج نطاق الخدمة → فشل الأهلية (FR-GEO-003) → رسالة OutOfServiceArea واضحة + إنهاء
   ↓
7. الموافقة الصريحة على الشروط والخصوصية (FR-AUTH-006)
   ↓
8. إنشاء الحساب وتهيئة المحافظ للعملات المفعلة (FR-AUTH-007) → SC-06 إنشاء PIN (إدخال + تأكيد)
   ↓
9. SC-07 تفعيل البصمة (اختياري — FR-AUTH-018)
   ↓
10. تسجيل الجهاز وإنشاء الجلسة (EP-AUTH)
    ─ فرع: جهاز غير موثوق/محظور → رفض الفحص الأمني → مسار الدعم (Master §8)
    ─ فرع: جهاز جديد → تنبيه أمني فوري SMS/إشعار (FR-AUTH-012)
    ↓
11. SC-08 الرئيسية: أرصدة KYC-0 من الخادم (حدود دنيا) + بطاقة "أكمل توثيقك" → SC-39 (FL-03)
```

## FL-02 — الدخول + PIN/البصمة

```text
1. SC-01: Version Check → System Check → Security Check → Session Check (Master §8)
   ─ فرع: Session Expired (حالة عالمية) → SC-03 مباشرة
   ↓
2. SC-03: رقم الهاتف المحفوظ + PIN
   ─ فرع: بصمة مفعلة على جهاز موثوق → قياس حيوي → نجاح → الخطوة 5
   ─ فرع: نسيان PIN → SC-04 OTP + تحقق إضافي (سؤال أمان/دعم — FR-AUTH-009) → SC-06 إعادة تعيين
   ─ فرع: جهاز جديد (لا ثقة) → SC-04 OTP + تنبيه أمني (FR-AUTH-012)
   ↓
3. تحقق PIN خادمياً (EP-AUTH)
   ─ فرع: 3 محاولات خاطئة → تأخير تصاعدي؛ 5 → قفل مؤقت + تنبيه أمني (FR-AUTH-017)
   ─ فرع: الحساب FROZEN → شاشة "الحساب مجمّد" (Master §145): السجل للقراءة + مسار SC-43/SC-46 + WhatsApp
   ─ فرع: الحساب RESTRICTED → بانر تقييد + الرئيسية بالوظائف المسموحة فقط
   ↓
4. إنشاء الجلسة + قفل الخلفية 60ث قابل للتهيئة (FR-AUTH-011)
   ↓
5. SC-08 الرئيسية: جلب الأرصدة وآخر العمليات من الخادم (EP-WLT/EP-TRX)
```

## FL-03 — التوثيق KYC (رفع / رفض / إعادة)

```text
1. مدخل: بطاقة "أكمل توثيقك" في SC-08 / SC-38 / إشعار KYC → Deep Link → SC-39 (Master §55)
   ↓
2. اختيار المستوى المستهدف (1: بطاقة + سيلفي / 2: + إثبات عنوان) وعرض الامتيازات
   ↓
3. التقاط/اختيار الصور → فحص جودة فوري (FR-KYC-002)
   ─ فرع: صورة غير واضحة/كبيرة → إرشاد محدد + إعادة الالتقاط
   ↓
4. (Should) التقاط GPS للمطابقة (FR-KYC-003) — ليس شرطاً وحيداً (R-06)
   ↓
5. رفع المستندات (EP-KYC → Storage موقّع — FR-KYC-006) → PENDING → UNDER_REVIEW
   ↓
6. طابور المدققين في لوحة التحكم (FR-KYC-007) مع فحص القوائم السوداء (FR-KYC-009)
   ↓
7. القرار يصل إشعاراً (FR-NTF-003) ويظهر في SC-39:
   ─ فرع: APPROVED → رفع الحدود فوراً (محرك الحدود FR-LDG-012) + SC-39 "مكتمل"
   ─ فرع: REJECTED → السبب + المراجع + وقت المراجعة (FR-KYC-005) → إعادة التقديم بعد مهلة السياسة
   ─ فرع: REQUIRES_UPDATE → طلب المستند المحدد فقط
   ─ فرع: EXPIRED (Could — FR-KYC-010) → إشعار تحديث المستندات
```

## FL-04 — تحويل ناجح كامل (quote → مراجعة → PIN → نتيجة → تحديث من الخادم)

```text
1. SC-08 → زر تحويل (أو مفضّل/إشعار/QR شخصي) → SC-11
   ↓
2. إدخال المستفيد: رقم/مفضل/QR → EP-TRF (lookup) → بطاقة مستفيد مقنّعة "أح*** م" (FR-TRF-001)
   ↓
3. العملة (CurrencyTabs) + المبلغ (AmountPad) → EP-TRF (quote)
   ─ فرع: Offline → R-02: زر المتابعة معطل + بانر "لا يوجد اتصال"
   ─ فرع: رصيد غير كافٍ/حد/خدمة → رسالة الخادم المحددة (FR-TRF-004)
   ↓
4. SC-12 مراجعة: المبلغ + الرسوم + الإجمالي + المستفيد + العملة (FR-TRF-003) — quote بصلاحية قصيرة
   ─ فرع: انتهت صلاحية quote → العودة إلى SC-11 لاقتباس جديد (لا تجديد صامت)
   ↓
5. "تأكيد وتحويل" → SC-13 PIN (أو بصمة)
   ─ فرع: PIN خاطئ → عدّاد محاولات FR-AUTH-017
   ↓
6. EP-TRF (execute) بمفتاح Idempotency فريد (FR-LDG-004) → تحقق خادمي كامل R-10:
   الأطراف/العملة/الرصيد/الحدود/الأهلية/التكرار/المخاطر (FR-TRF-004)
   ↓
7. عملية ذرّية: قفل → خصم → رسوم → إضافة → Ledger متوازن → Commit (FR-LDG-002/003)
   ↓
8. SC-14: النتيجة من الخادم فقط (Master §86) — ReceiptCard بالمرجع SW-YYYYMMDD-XXXXXXXX
   ↓
9. إشعار فوري للمرسل والمستلم (FR-TRF-005 / Master §88) + عرض "إضافة مفضّل" (FR-FAV-002)
   ↓
10. "تم" → SC-08: إعادة جلب الأرصدة وآخر العمليات من الخادم (Master §87)
    (Wallet Balance refreshed + Recent Transactions refreshed — لا old_balance − amount)
```

## FL-05 — تحويل فاشل / انقطاع الإنترنت بعد الإرسال

```text
1. الخطوات 1..6 كما FL-04 حتى إرسال EP-TRF (execute)
   ↓
2. انقطاع الاتصال بعد إرسال الطلب وقبل وصول الاستجابة
   ↓
3. SC-14 يعرض Pending: "قيد التنفيذ — بانتظار الاتصال" (لا نجاح ولا فشل — FR-TOP-004 نفس المبدأ)
   ↓
4. عند عودة الاتصال (FR-OFF-003): استعلام العملية الأصلية نفسها بالمرجع/Idempotency (Master §114)
   قاعدة: لا يُنشأ طلب تحويل جديد أبداً
   ↓
5. النتيجة الفعلية للعملية الأصلية من الخادم:
   ─ فرع: COMPLETED → عرض النجاح + الإيصال + تحديث الرئيسية من الخادم (§87)
   ─ فرع: FAILED/REJECTED → السبب + زر "محاولة جديدة" (طلب جديد بIdempotency جديد) + تذكرة §106
   ─ فرع: ما تزال PROCESSING → StatusChip كهرماني + زر "تحديث الحالة" يستعلم نفس العملية
   ↓
6. إشعار المستخدم بحالة العملية النهائية عند اكتمالها (FR-NTF-002)
```

## FL-06 — حوالة كاملة (إنشاء → رمز → تسليم عند وكيل → مكتملة)

```text
1. الخدمات → الحوالات → SC-16: المبلغ + العملة + بيانات المستلم (اسم + هاتف) + المدينة/الوكيل المقترح
   ↓
2. quote الرسوم + عمولة الوكيل (FR-REM-007) → مراجعة → SC-13 PIN → EP-REM (create)
   ↓
3. التنفيذ الخادمي: خصم المبلغ من المرسل + حجز لدى النظام (Ledger) + توليد رمز تسليم
   يعمل مرة واحدة بصلاحية قابلة للتهيئة (FR-REM-002)
   ↓
4. SC-14 إيصال الإنشاء → SC-17 التتبع: "قيد التسليم" + مشاركة الرمز/QR مع المستلم
   + إشعار SMS للمستلم غير المشترك (FR-REM-004)
   ↓
5. المستلم يذهب إلى الوكيل (SC-26) → SC-50 تسليم الحوالة: رمز التسليم + هويته → تحقق خادمي
   → تسليم النقد → تسجيل التسليم (FR-REM-003)
   ↓
6. COMPLETED: إشعار للمرسل + إيصال + عمولة الوكيل على Float/التسوية (FR-CWD-007)
   ─ فرع إلغاء: المرسل يلغي قبل التسليم (SC-17) → استرداد للمحفظة عبر Reversal (FR-REM-005)
   ─ فرع انتهاء: انتهاء صلاحية الحوالة (FR-REM-008) → إرجاع تلقائي + إشعار + حالة "منتهية"
```

## FL-07 — سحب نقدي (Hold → رمز → تسليم → إتمام)

```text
1. SC-08 → زر سحب → SC-23: العملة + المبلغ + الوكيل (من SC-25/SC-26)
   ↓
2. عرض الرسوم والحدود الدنيا/العليا (FR-CWD-005) → مراجعة → SC-13 PIN
   ↓
3. EP-CASH (withdraw-request): Hold على المبلغ (رصيد مجمّد — FR-WLT-008) + رمز سحب بصلاحية
   → SC-24 (READY_FOR_COLLECTION بمؤقت)
   ↓
4. الوكيل: SC-49 مسح/إدخال الرمز + تحقق هوية المستلم → تحقق خادمي → تسليم النقد
   → COLLECTED (FR-CWD-002)
   ↓
5. COMPLETED: إتمام Ledger + تحديث Float (FR-CWD-007) + إيصال + إشعار للمستخدم
   ─ فرع انتهاء المهلة: EXPIRED → تحرير المبلغ المجمّد تلقائياً (Reversal) + إشعار (FR-CWD-003)
   ─ فرع إلغاء قبل القبض: المستخدم يلغي من SC-24 → نفس مسار تحرير Hold
```

## FL-08 — إيداع عبر وكيل (طلب → تأكيد الوكيل → رصيد)

```text
1. SC-08 → زر إيداع → SC-22: المبلغ + العملة + الوكيل → EP-CASH (deposit-request) → PENDING
   ↓
2. عرض "اذهب للوكيل خلال المهلة" + عدّاد (Master §21)
   ↓
3. الوكيل يستلم النقد → SC-48: التحقق من هوية العميل → تأكيد الاستلام
   ─ فرع: الوكيل يرفض بسبب → REJECTED + إشعار المستخدم بالسبب (FR-CWD-006)
   ─ فرع: انتهاء المهلة → EXPIED → إشعار + طلب جديد عند الحاجة
   ↓
4. تحقق الخادم → Ledger → إضافة رصيد المستخدم (Wallet Credit) → COMPLETED
   ↓
5. إشعار فوري للمستخدم + تحديث الرئيسية من الخادم (§87) + انعكاس فوري على Float الوكيل (FR-CWD-007)
```

## FL-09 — دفع QR (مسح → حل خادمي → مراجعة → PIN → إيصال)

```text
1. SC-08 → زر دفع → SC-19 مسح QR
   ↓
2. إرسال الحمولة كما هي إلى EP-PAY (resolve) — لا فك توقيع محلي (FR-PAY-001 / R-10)
   ─ فرع: QR غير موقّع/منتهٍ/جهة لا يمكن التحقق منها → رفض صريح (FR-PAY-007) + رسالة + العودة للمسح
   ↓
3. SC-20: التاجر (الاسم/الفرع/نقطة البيع من الخادم) + المبلغ (ثابت من QR أو AmountPad) + الرسوم (quote)
   ↓
4. مراجعة → SC-13 PIN
   ─ فرع: رصيد/حدود/مخاطر → رسالة الخادم (FR-PAY-003)
   ↓
5. EP-PAY (execute) بIdempotency → عملية ذرّية → Merchant Credit (FR-PAY-003)
   ↓
6. SC-14 إيصال للعميل + إشعار فوري للتاجر (US-MRC-006) + تحديث مدفوعات التاجر (SC-54)
```

## FL-10 — دفع POSCOF (رقم نقطة البيع)

```text
1. SC-08 → زر دفع → SC-20 تبويب "رقم نقطة البيع"
   ↓
2. إدخال رقم POSCOF يدوياً → EP-PAY (resolve) (FR-PAY-002)
   ─ فرع: رقم غير موجود/معطل → رسالة صريحة + لا متابعة
   ↓
3. عرض اسم التاجر ونقطة البيع (إلزامي قبل التأكيد) → المبلغ (AmountPad) → الرسوم (quote)
   ↓
4. مراجعة (المبلغ + الرسوم + التاجر) → SC-13 PIN → تحقق (مخاطر + حدود + رصيد)
   ↓
5. عملية ذرّية → إيصال للطرفين (FR-PAY-003) + إشعار للتاجر (Master §88)
```

## FL-11 — شحن رصيد (Pending حتى نتيجة المزود)

```text
1. SC-09 → شحن الرصيد → SC-27: الشبكة → الرقم (تحقق الصيغة — FR-TOP-002) → المنتج/الفئة
   ↓
2. السعر + الرسوم → مراجعة → SC-13 PIN → EP-TOP (execute) بIdempotency
   ↓
3. الحالة Pending معروضة بوضوح: "جارٍ التأكد من المزود…" (FR-TOP-004 — لا "نجاح" قبل النتيجة)
   ↓
4. نتيجة المزود الفعلية (EP-TOP status / Webhook):
   ─ فرع: نجاح → COMPLETED + إيصال + تحديث الرصيد من الخادم (§87)
   ─ فرع: فشل المزود → سياسة الفشل Pending → Retry → Refund (Master §69) + إشعار + حالة معلنة في السجل
   ─ فرع: انقطاع بالمزود → إعادة محاولة آمنة بالIdempotency + استرجاع تلقائي وفق السياسة (FR-TOP-005)
   ↓
5. سجل الشحنات السريع يتحدث (FR-TOP-006)
```

## FL-12 — سداد فاتورة

```text
1. SC-09 → الفواتير → SC-28: المزود (مُدار — FR-BIL-003) → رقم المشترك → استعلام (EP-BIL inquiry)
   ─ فرع: مزود يدعم الاستعلام → عرض المستحق (لا تعديل المبلغ — FR-BIL-002 إلا بسياسة دفع جزئي)
   ─ فرع: مزود بلا استعلام → إدخال المبلغ وفق قاعدة المزود
   ↓
2. مراجعة (المستحق + الرسوم) → SC-13 PIN → EP-BIL (execute)
   ↓
3. الحالة Pending حتى نتيجة المزود (نفس مبدأ FL-11)
   ─ فرع: فشل المزود بعد الخصم → Pending → Retry → Refund (FR-BIL-004) + إشعار + حالة في السجل
   ↓
4. COMPLETED → إيصال (رقم المشترك + المرجع) + حفظ Payer للاستخدام المتكرر (FR-BIL-005)
```

## FL-13 — شراء كرت شبكة (الكود بعد الدفع فقط)

```text
1. SC-09 → كروت الشبكة → SC-29: الشبكة → الفئة (توفر المخزون من EP-TOP — FR-NWC-001)
   ↓
2. السعر + الرسوم → مراجعة → SC-13 PIN → EP-TOP (reserve/execute)
   ↓
3. الخصم أولاً → حجز الكرت من المخزون المركزي (FR-NWC-002)
   ─ فرع: فشل الدفع → لا استهلاك للكرت + تحرير الحجز + رسالة واضحة
   ↓
4. نجاح الدفع فقط → عرض الكود: حقل نسخ + QR + ملاحظة الصلاحية (FR-NWC-003)
   ↓
5. إعادة العرض لاحقاً من SC-35 "تفاصيل العملية" (وفق صلاحية العرض الأمنية) + إيصال العملية
```

## FL-14 — الحصالة (إنشاء هدف → إيداع)

```text
1. SC-09 → الحصالة → SC-30 (نظرة عامة — الأهداف والإجمالي من EP-SAV)
   ↓
2. SC-31 هدف جديد: العنوان + المبلغ المستهدف + العملة (+ تاريخ اختياري) → إنشاء (FR-SAV-001)
   ↓
3. SC-32 إيداع: المبلغ من المحفظة → بطاقة مراجعة → SC-13 PIN → EP-SAV (move)
   ↓
4. تنفيذ عبر Ledger فعلي (محفظة → حصالة — FR-SAV-002/FR-TRF-009) — ليس رقماً وهمياً
   ↓
5. SC-33: التقدم يرتفع + الإحصاءات (FR-SAV-004) + سجل الحصالة المنفصل (FR-SAV-006) + إشعار
   ─ فرع سحب من الحصالة: نفس المسار معكوساً (SC-32 وضع السحب → PIN → Ledger → المحفظة)
```

## FL-15 — الإبلاغ عن مشكلة من تفاصيل العملية (تذكرة مرتبطة + WhatsApp)

```text
1. SC-34 السجل → SC-35 تفاصيل العملية (بيانات من الخادم — Master §86)
   ↓
2. زر "الإبلاغ عن مشكلة" → SC-44 تذكرة جديدة والعملية مرتبطة تلقائياً (Master §106 —
   لا كتابة رقم العملية يدوياً) (FR-SUP-002)
   ↓
3. الفئة + الوصف (+ مرفقات اختيارية) → إنشاء (EP-SUP) → SC-45 محادثة التذكرة
   ↓
4. الدعم يحقق عبر مسار Master §144: مراجعة التذكرة → فحص المعاملة → Ledger Check → Provider Check
   → القرار:
   ─ فرع: Retry (إعادة آمنة بالIdempotency) / Reverse (عكس موثق) / Refund / Reject (رفض مسبب)
   ─ فرع أي تعديل مالي → Ledger Adjustment + Audit + إشعار المستخدم (FR-LDG-007)
   ↓
5. إغلاق التذكرة (RESOLVED → CLOSED) + تقييم الرضا (FR-SUP-006) + إشعار بالنتيجة
   ↓
6. مسار مواز من SC-35/SC-45: زر WhatsApp → SC-46: بناء رسالة آمنة بالمرجع والبيانات المسموحة فقط
```

# 9. إمكانية الوصول (Accessibility — SRS §7.5)

| البند | المواصفة |
|---|---|
| التباين | نسبة تباين ≥ AA (4.5:1 للنصوص الأساسية) على الثيمين الفاتح والداكن — تم التحقق لأزواج الألوان في §2.1 (ذهبي الجنوب للتمييز على الأسطح الدافئة فقط لا للنص الصغير) |
| قارئ الشاشة | تسميات Semantics عربية لكل عنصر تفاعلي أساسي (الأزرار، صفوف العمليات، بطاقات الأرصدة، لوحات الأرقام)؛ قراءة المبلغ بصيغة "خمسمائة ريال يمني" لا "500" |
| تكبير الخطوط | دعم أحجام خط النظام حتى 130% دون كسر التخطيط (الشبكة 4pt والصفوف المرنة) |
| أهداف اللمس | 44×44px حد أدنى لكل عنصر تفاعلي (NFR-USE-002) مع تباعد 8px بين الأهداف المتجاورة |
| الاتجاه | كل الاختبارات الأساسية بالعربية RTL أولاً ثم الإنجليزية LTR (R-11) — كل مكوّن يُختبر بالعربية قبل اعتماده (Master §92) |
| إشارات بديلة | الحالة لا تُميَّز باللون وحده: أيقونة + نص لكل StatusChip (للمستخدمين ضعاف تمييز الألوان) |
