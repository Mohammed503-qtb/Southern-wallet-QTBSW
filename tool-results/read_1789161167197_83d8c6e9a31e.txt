    19→    19→# 1. المقدمة
    20→    20→
    21→    21→## 1.1 الغرض
    22→    22→
    23→    23→تحدد هذه الوثيقة المتطلبات الوظيفية وغير الوظيفية لمنظومة **محفظة الجنوب** — محفظة مالية رقمية تعمل على Android وiOS ضمن نطاق جغرافي محدد في جنوب اليمن. وهي المرجع التعاقدي والتقني لـ:
    24→    24→
    25→    25→- صاحب المنتج — لاعتماد نطاق العمل والموافقة على المعايير.
    26→    26→- فريق الهندسة — لتصميم المعمارية وقاعدة البيانات وواجهات البرمجة.
    27→    27→- فرق الجودة والاختبار — لبناء حالات الاختبار والقبول.
    28→    28→- فريق الامتثال والمخاطر — لمراجعة ضوابط KYC/AML/CFT.
    29→    29→
    30→    30→## 1.2 نطاق المنتج
    31→    31→
    32→    32→**محفظة الجنوب** منظومة مالية رقمية متكاملة تقدّم للمستخدم المؤهَّل داخل نطاق الخدمة:
    33→    33→
    34→    34→- محفظة متعددة العملات (YER / SAR / USD).
    35→    35→- التحويل الفوري بين مشتركي المحفظة، والتحويل بين محافظ المستخدم نفسه.
    36→    36→- حوالات مالية إلى غير المشتركين واستلامها عبر شبكة وكلاء ونقاط خدمة معتمدة.
    37→    37→- الدفع عبر QR Code أو رقم نقطة البيع لدى التجار.
    38→    38→- سداد الفواتير وشحن رصيد الجوال لجميع الشبكات المحلية.
    39→    39→- السحب والإيداع النقدي عبر الوكلاء.
    40→    40→- صندوق توفير ذكي (الحصالة)، كروت الشبكة، كشف حساب مفصل، إشعارات فورية، مفضلون، ودعم متكامل.
    41→    41→
    42→    42→يقدّم النظام أيضاً **لوحة تحكم إدارية** لإدارة المستخدمين والتوثيق والوكلاء والتجار والرسوم والحدود والتسويات ومكافحة الاحتيال والتقارير وسجل التدقيق.
    43→    43→
    44→    44→**خارج النطاق (Out of Scope):**
    45→    45→- الإقراض أو التمويل الصغير أو أي منتج ائتماني.
    46→    46→- التداول في العملات الرقمية كخدمة أساسية (مؤجل لمرحلة ما بعد الإطلاق، ومشروط بطبقة Custody مستقلة).
    47→    47→- أي عملية مصرفية تتطلب ترخيصاً مصرفياً كاملاً ما لم يُستوفَ نظامياً.
    48→    48→
    49→    49→## 1.3 نظرة عامة على المنظومة
    50→    50→
    51→    51→```
    52→    52→        ┌─────────────────────┐
    53→    53→        │   تطبيق Flutter     │  ← عميل / وكيل / تاجر
    54→    54→        │  Android + iOS      │
    55→    55→        └─────────┬───────────┘
    56→    56→                  │ HTTPS / TLS 1.2+
    57→    57→        ┌─────────▼───────────┐
    58→    58→        │    Backend API      │  Authentication → Authorization →
    59→    59→        │  (Node.js/NestJS)   │  Eligibility → Risk → Limits →
    60→    60→        │                     │  Transaction Engine → Ledger
    61→    61→        └───┬──────┬──────┬───┘
    62→    62→            │      │      │
    63→    63→   ┌────────▼┐ ┌──▼───┐ ┌▼─────────────┐
    64→    64→   │PostgreSQL│ │Redis │ │ مزودون خارجيون │
    65→    65→   │ + Ledger │ │Cache │ │ SMS / FCM /   │
    66→    66→   └──────────┘ └──────┘ │ شحن / فواتير / │
    67→    67→                          │ شبكات صرافة   │
    68→    68→                          └───────────────┘
    69→    69→        ┌─────────────────────┐
    70→    70→        │  لوحة تحكم ويب (RTL) │  ← الإدارة بكل أدوارها
    71→    71→        └─────────────────────┘
    72→    72→```
    73→    73→
    74→    74→**المبدأ التأسيسي:** قاعدة الحقيقة المالية هي الخادم + دفتر الأستاذ (Ledger)، وليس التطبيق أبداً. التطبيق يعرض الحالة وينقل الطلب ويعرض النتيجة؛ كل قرار مالي يُتخذ ويُسجَّل في الخادم.

    87→    87→## 1.5 المصطلحات والتعريفات
    88→    88→
    89→    89→| المصطلح | التعريف |
    90→    90→|---|---|
    91→    91→| **OTP** | كلمة مرور لمرة واحدة تُرسل عبر SMS للتحقق من ملكية رقم الهاتف |
    92→    92→| **KYC** | اعرف عميلك — توثيق هوية المستخدم (هوية، صورة، عنوان، موقع) |
    93→    93→| **AML/CFT** | مكافحة غسل الأموال وتمويل الإرهاب |
    94→    94→| **Ledger** | دفتر الأستاذ — سجل محاسبي غير قابل للتعديل لكل حركة مالية |
    95→    95→| **Idempotency** | خاصية تضمن أن تكرار نفس الطلب لا ينتج عملية مالية مزدوجة |
    96→    96→| **Atomicity** | خاصية "كلها أو لا شيء" لتنفيذ المعاملة المالية |
    97→    97→| **Geofencing** | تقييد الخدمة جغرافياً ضمن حدود إدارية معرّفة |
    98→    98→| **GPS Spoofing** | تزييف الموقع الجغرافي على الجهاز |
    99→    99→| **Device Fingerprint** | بصمة فريدة للجهاز تميّزه عن غيره |
   100→   100→| **Float (الوكيل)** | رصيد التشغيل النقدي المتاح لدى الوكيل لتنفيذ السحب |
   101→   101→| **Settlement (التسوية)** | مطابقة أرصدة المحافظ مع دفتر الأستاذ ومع الوكلاء والتجار والمزودين |
   102→   102→| **Reversal** | عملية عكسية تصحح معاملة سابقة دون تعديلها |
   103→   103→| **PIN** | رمز رقمي سري يثبت نيّة المستخدم في العمليات الحساسة |
   104→   104→| **POSCOF** | رقم نقطة البيع / رقم التاجر |
   105→   105→| **QR Code** | رمز استجابة سريعة يحمل بيانات دفع موقّعة |
   106→   106→| **MoSCoW** | تصنيف الأولوية: Must / Should / Could / Won't |
   107→   107→| **DoD** | Definition of Done — معيار اكتمال الوظيفة |
   108→   108→| **YER / SAR / USD** | الريال اليمني / الريال السعودي / الدولار الأمريكي |

   110→   110→## 1.6 القواعد الجوهرية غير القابلة للتفاوض
   111→   111→
   112→   112→مستمدة من Master PLAN.md وتُعد قيوداً حاكمة على كل متطلب في هذه الوثيقة:
   113→   113→
   114→   114→| # | القاعدة |
   115→   115→|---|---|
   116→   116→| R-01 | الخادم + Ledger هما مصدر الحقيقة المالية؛ يُمنع جعل التطبيق أو التخزين المحلي مصدراً للرصيد |
   117→   117→| R-02 | يُمنع تنفيذ أي عملية مالية Offline أو خصم الرصيد محلياً |
   118→   118→| R-03 | كل عملية مالية ذرّية (Atomic) وقابلة للتماثل (Idempotent) ومسجّلة في Ledger |
   119→   119→| R-04 | المعاملة المكتملة لا تُعدَّل أبداً؛ التصحيح يكون بـ Reversal/Adjustment موثّق |
   120→   120→| R-05 | لا "زر تعديل رصيد" مباشر للإدارة؛ كل تعديل مالي يمر عبر Adjustment Request + موافقة + Ledger + Audit |
   121→   121→| R-06 | GPS ليس الحكم الوحيد للأهلية الجغرافية؛ القرار الجغرافي خطير لا يُبنى على إشارة موقع واحدة غير موثوقة |
   122→   122→| R-07 | يُمنع وضع أي أسرار (API Secrets / مفاتيح / كلمات مرور) داخل تطبيق Flutter |
   123→   123→| R-08 | لا بيانات وهمية أو Mock Providers أو نجاح مصطنع في بيئة الإنتاج |
   124→   124→| R-09 | أي وظيفة جديدة يجب أن تكتمل: بيانات + صلاحيات + API + حالات + إشعارات + تحكم إداري + تدقيق + تقارير |
   125→   125→| R-10 | التطبيق يُعد غير موثوق؛ الخادم يعيد التحقق من كل شيء (المبالغ، الرسوم، المستلم، الحدود، الحالة) |
   126→   126→| R-11 | العربية RTL جزء من التصميم من اليوم الأول، وليست إضافة لاحقة |
   127→   127→| R-12 | التطبيق الأصلي Flutter (ليس WebView)؛ الهوية والشعار والأيقونات أصلية خاصة بمحفظة الجنوب |
   128→   128→| R-13 | عدم وصول Push Notification لا يعني فشل العملية؛ الإشعار قناة إبلاغ فقط |
   129→   129→| R-14 | البيانات المالية وسجلات التدقيق لا تُحذف لأي سبب تنظيفي؛ الحذف المنطقي للمحتوى فقط |

   135→   135→## 2.1 منظور المنتج
   136→   136→
   137→   137→المنتج منظومة متكاملة من أربعة مكونات مترابطة تعمل على مصدر حقيقة واحد:
   138→   138→
   139→   139→1. **تطبيق الموبايل (Flutter):** واجهة العميل والوكيل والتاجر — عربي RTL أولاً مع إنجليزية، يعمل بخدمات المصادقة الآمنة والتخزين المحلي غير المالي.
   140→   140→2. **Backend API (Node.js/NestJS):** القلب المالي — المصادقة، الصلاحيات، الأهلية، محرك المخاطر، الحدود، الرسوم، محرك المعاملات، Ledger، التسويات.
   141→   141→3. **قاعدة البيانات (PostgreSQL + Redis):** التخزين المعاملاتي الدائم + الكاش والجلسات.
   142→   142→4. **لوحة التحكم الإدارية (ويب RTL):** إدارة كاملة للمنظومة بسبعة أدوار إدارية مع Audit شامل.

   343→   343→## 4.4 محرك المعاملات ودفتر الأستاذ (FR-LDG)
   344→   344→

   346→   346→
   347→   347→```
   348→   348→CREATED → VALIDATING → AUTHORIZED → PROCESSING → COMPLETED

   353→   353→```

   814→   814→## 7.4 مبادئ UX
   815→   815→
   816→   816→- **البساطة أولاً:** الأزرار الأساسية (تحويل/إيداع/سحب/دفع) بارزة في الرئيسية، والخدمات شبكة واضحة.
   817→   817→- **السرعة:** تحميل تدريجي، Skeletons، تحديث بعد كل عملية من الخادم (لا حساب محلي للرصيد).
   818→   818→- **الوضوح المالي:** المبلغ/الرسوم/الإجمالي قبل أي تأكيد — لا مفاجآت.
   819→   819→- **الأمان المرئي:** إخفاء الأرصدة اختياري، إشعارات الأحداث الأمنية، شاشة إعادة PIN عند العمليات الحساسة.
   820→   820→- **RTL أصيل:** كل الاختبارات الأساسية بالعربية RTL أولاً ثم الإنجليزية.
