    19→# 1. المقدمة
    20→
    21→## 1.1 الغرض
    22→
    23→تحدد هذه الوثيقة المتطلبات الوظيفية وغير الوظيفية لمنظومة **محفظة الجنوب** — محفظة مالية رقمية تعمل على Android وiOS ضمن نطاق جغرافي محدد في جنوب اليمن. وهي المرجع التعاقدي والتقني لـ:
    24→
    25→- صاحب المنتج — لاعتماد نطاق العمل والموافقة على المعايير.
    26→- فريق الهندسة — لتصميم المعمارية وقاعدة البيانات وواجهات البرمجة.
    27→- فرق الجودة والاختبار — لبناء حالات الاختبار والقبول.
    28→- فريق الامتثال والمخاطر — لمراجعة ضوابط KYC/AML/CFT.
    29→
    30→## 1.2 نطاق المنتج
    31→
    32→**محفظة الجنوب** منظومة مالية رقمية متكاملة تقدّم للمستخدم المؤهَّل داخل نطاق الخدمة:
    33→
    34→- محفظة متعددة العملات (YER / SAR / USD).
    35→- التحويل الفوري بين مشتركي المحفظة، والتحويل بين محافظ المستخدم نفسه.
    36→- حوالات مالية إلى غير المشتركين واستلامها عبر شبكة وكلاء ونقاط خدمة معتمدة.
    37→- الدفع عبر QR Code أو رقم نقطة البيع لدى التجار.
    38→- سداد الفواتير وشحن رصيد الجوال لجميع الشبكات المحلية.
    39→- السحب والإيداع النقدي عبر الوكلاء.
    40→- صندوق توفير ذكي (الحصالة)، كروت الشبكة، كشف حساب مفصل، إشعارات فورية، مفضلون، ودعم متكامل.
    41→
    42→يقدّم النظام أيضاً **لوحة تحكم إدارية** لإدارة المستخدمين والتوثيق والوكلاء والتجار والرسوم والحدود والتسويات ومكافحة الاحتيال والتقارير وسجل التدقيق.
    43→
    44→**خارج النطاق (Out of Scope):**
    45→- الإقراض أو التمويل الصغير أو أي منتج ائتماني.
    46→- التداول في العملات الرقمية كخدمة أساسية (مؤجل لمرحلة ما بعد الإطلاق، ومشروط بطبقة Custody مستقلة).
    47→- أي عملية مصرفية تتطلب ترخيصاً مصرفياً كاملاً ما لم يُستوفَ نظامياً.
    48→
    49→## 1.3 نظرة عامة على المنظومة
    50→
    51→```
    52→        ┌─────────────────────┐
    53→        │   تطبيق Flutter     │  ← عميل / وكيل / تاجر
    54→        │  Android + iOS      │
    55→        └─────────┬───────────┘
    56→                  │ HTTPS / TLS 1.2+
    57→        ┌─────────▼───────────┐
    58→        │    Backend API      │  Authentication → Authorization →
    59→        │  (Node.js/NestJS)   │  Eligibility → Risk → Limits →
    60→        │                     │  Transaction Engine → Ledger
    61→        └───┬──────┬──────┬───┘
    62→            │      │      │
    63→   ┌────────▼┐ ┌──▼───┐ ┌▼─────────────┐
    64→   │PostgreSQL│ │Redis │ │ مزودون خارجيون │
    65→   │ + Ledger │ │Cache │ │ SMS / FCM /   │
    66→   └──────────┘ └──────┘ │ شحن / فواتير / │
    67→                          │ شبكات صرافة   │
    68→                          └───────────────┘
    69→        ┌─────────────────────┐
    70→        │  لوحة تحكم ويب (RTL) │  ← الإدارة بكل أدوارها
    71→        └─────────────────────┘
    72→```
    73→
    74→**المبدأ التأسيسي:** قاعدة الحقيقة المالية هي الخادم + دفتر الأستاذ (Ledger)، وليس التطبيق أبداً. التطبيق يعرض الحالة وينقل الطلب ويعرض النتيجة؛ كل قرار مالي يُتخذ ويُسجَّل في الخادم.

    87→## 1.5 المصطلحات والتعريفات
    88→
    89→| المصطلح | التعريف |
    90→|---|---|
    91→| **OTP** | كلمة مرور لمرة واحدة تُرسل عبر SMS للتحقق من ملكية رقم الهاتف |
    92→| **KYC** | اعرف عميلك — توثيق هوية المستخدم (هوية، صورة، عنوان، موقع) |
    93→| **AML/CFT** | مكافحة غسل الأموال وتمويل الإرهاب |
    94→| **Ledger** | دفتر الأستاذ — سجل محاسبي غير قابل للتعديل لكل حركة مالية |
    95→| **Idempotency** | خاصية تضمن أن تكرار نفس الطلب لا ينتج عملية مالية مزدوجة |
    96→| **Atomicity** | خاصية "كلها أو لا شيء" لتنفيذ المعاملة المالية |
    97→| **Geofencing** | تقييد الخدمة جغرافياً ضمن حدود إدارية معرّفة |
    98→| **GPS Spoofing** | تزييف الموقع الجغرافي على الجهاز |
    99→| **Device Fingerprint** | بصمة فريدة للجهاز تميّزه عن غيره |
   100→| **Float (الوكيل)** | رصيد التشغيل النقدي المتاح لدى الوكيل لتنفيذ السحب |
   101→| **Settlement (التسوية)** | مطابقة أرصدة المحافظ مع دفتر الأستاذ ومع الوكلاء والتجار والمزودين |
   102→| **Reversal** | عملية عكسية تصحح معاملة سابقة دون تعديلها |
   103→| **PIN** | رمز رقمي سري يثبت نيّة المستخدم في العمليات الحساسة |
   104→| **POSCOF** | رقم نقطة البيع / رقم التاجر |
   105→| **QR Code** | رمز استجابة سريعة يحمل بيانات دفع موقّعة |
   106→| **MoSCoW** | تصنيف الأولوية: Must / Should / Could / Won't |
   107→| **DoD** | Definition of Done — معيار اكتمال الوظيفة |
   108→| **YER / SAR / USD** | الريال اليمني / الريال السعودي / الدولار الأمريكي |

   110→## 1.6 القواعد الجوهرية غير القابلة للتفاوض
   111→
   112→مستمدة من Master PLAN.md وتُعد قيوداً حاكمة على كل متطلب في هذه الوثيقة:
   113→
   114→| # | القاعدة |
   115→|---|---|
   116→| R-01 | الخادم + Ledger هما مصدر الحقيقة المالية؛ يُمنع جعل التطبيق أو التخزين المحلي مصدراً للرصيد |
   117→| R-02 | يُمنع تنفيذ أي عملية مالية Offline أو خصم الرصيد محلياً |
   118→| R-03 | كل عملية مالية ذرّية (Atomic) وقابلة للتماثل (Idempotent) ومسجّلة في Ledger |
   119→| R-04 | المعاملة المكتملة لا تُعدَّل أبداً؛ التصحيح يكون بـ Reversal/Adjustment موثّق |
   120→| R-05 | لا "زر تعديل رصيد" مباشر للإدارة؛ كل تعديل مالي يمر عبر Adjustment Request + موافقة + Ledger + Audit |
   121→| R-06 | GPS ليس الحكم الوحيد للأهلية الجغرافية؛ القرار الجغرافي خطير لا يُبنى على إشارة موقع واحدة غير موثوقة |
   122→| R-07 | يُمنع وضع أي أسرار (API Secrets / مفاتيح / كلمات مرور) داخل تطبيق Flutter |
   123→| R-08 | لا بيانات وهمية أو Mock Providers أو نجاح مصطنع في بيئة الإنتاج |
   124→| R-09 | أي وظيفة جديدة يجب أن تكتمل: بيانات + صلاحيات + API + حالات + إشعارات + تحكم إداري + تدقيق + تقارير |
   125→| R-10 | التطبيق يُعد غير موثوق؛ الخادم يعيد التحقق من كل شيء (المبالغ، الرسوم، المستلم، الحدود، الحالة) |
   126→| R-11 | العربية RTL جزء من التصميم من اليوم الأول، وليست إضافة لاحقة |
   127→| R-12 | التطبيق الأصلي Flutter (ليس WebView)؛ الهوية والشعار والأيقونات أصلية خاصة بمحفظة الجنوب |
   128→| R-13 | عدم وصول Push Notification لا يعني فشل العملية؛ الإشعار قناة إبلاغ فقط |
   129→| R-14 | البيانات المالية وسجلات التدقيق لا تُحذف لأي سبب تنظيفي؛ الحذف المنطقي للمحتوى فقط |

   133→# 2. الوصف العام

   135→## 2.1 منظور المنتج
   136→
   137→المنتج منظومة متكاملة من أربعة مكونات مترابطة تعمل على مصدر حقيقة واحد:
   138→
   139→1. **تطبيق الموبايل (Flutter):** واجهة العميل والوكيل والتاجر — عربي RTL أولاً مع إنجليزية، يعمل بخدمات المصادقة الآمنة والتخزين المحلي غير المالي.
   140→2. **Backend API (Node.js/NestJS):** القلب المالي — المصادقة، الصلاحيات، الأهلية، محرك المخاطر، الحدود، الرسوم، محرك المعاملات، Ledger، التسويات.
   141→3. **قاعدة البيانات (PostgreSQL + Redis):** التخزين المعاملاتي الدائم + الكاش والجلسات.
   142→4. **لوحة التحكم الإدارية (ويب RTL):** إدارة كاملة للمنظومة بسبعة أدوار إدارية مع Audit شامل.

   226→## 3.2 المتطلبات الوظيفية — النطاق والأهلية
   227→
   228→| ID | المتطلب | الأولوية |
   229→|---|---|---|
   230→| FR-GEO-001 | يعمل النظام بنظام جغرافي مركزي (regions / districts / areas / eligibility_policies) قابل للإدارة من لوحة التحكم؛ لا قائمة مناطق ثابتة في كود التطبيق | Must |
   231→| FR-GEO-002 | كل منطقة تملك: المعرّف، الاسم، الرمز، التفعيل، السماح بالتسجيل، السماح بالمعاملات، ملاحظات | Must |
   232→| FR-GEO-003 | يُمنع التسجيل الجديد من خارج نطاق الخدمة مع رسالة واضحة "الخدمة غير متاحة في منطقتك حالياً" | Must |
   233→| FR-GEO-004 | تقييم الأهلية متعدد الإشارات: المنطقة المسجلة + بيانات التوثيق + رقم الهاتف (مقدّم الخدمة/الرمز) + الإشارات الجغرافية + حالة الحساب + سياسة المنطقة + إشارات الأمان | Must |
   234→| FR-GEO-005 | GPS إشارة مساعدة فقط، ولا يُبنى عليه قرار مالي خطير منفرداً | Must |
   235→| FR-GEO-006 | عند محاولة استخدام من خارج النطاق: تقييد العمليات الحساسة أو إيقاف مؤقت مع إشعار للدعم — دون حذف الحساب أو الأموال | Must |
   236→| FR-GEO-007 | كشف التلاعب بالموقع (GPS Spoofing): فحص mock location APIs، تناقض موقع سريع (سرعة انتقال غير منطقية)، وتناقض GPS مع IP وبصمة الجهاز | Must |

   343→## 4.4 محرك المعاملات ودفتر الأستاذ (FR-LDG)
   344→
   345→**حالات المعاملة (State Machine):**
   346→
   347→```
   348→CREATED → VALIDATING → AUTHORIZED → PROCESSING → COMPLETED
   349→أي من الحالات السابقة يمكن أن تنتهي بـ:
   350→FAILED / REJECTED / CANCELLED / EXPIRED
   351→COMPLETED يمكن أن يتبعها REVERSED
   352→وأي عملية تحت مراجعة: UNDER_REVIEW
   353→```
   354→
   355→لا انتقالات عشوائية؛ كل انتقال مسموح معرّف ومسجّل في `transaction_status_history`.
   356→
   357→| ID | المتطلب | الأولوية |
   358→|---|---|---|
   359→| FR-LDG-001 | كل تغيير فعلي في الأموال يولّد Ledger Entries متوازنة (مدين/دائن) تشمل أطراف العملية وحساب الرسوم | Must |
   360→| FR-LDG-002 | مثال التحويل: مدين محفظة المرسل → دائن محفظة المستلم + دائن حساب الرسوم؛ المجموع صفر دائماً (Double-Entry) | Must |
   361→| FR-LDG-003 | كل عملية مالية ذرّية: تحقق → قفل سجلات → خصم → رسوم → إضافة → Ledger → Commit، أو Rollback كامل | Must |
   362→| FR-LDG-004 | كل طلب عملية حساسة يحمل مفتاح Idempotency فريد؛ نفس المفتاح = نفس النتيجة دون تنفيذ مزدوج | Must |
   363→| FR-LDG-005 | مرجع معاملة فريد بصيغة `SW-YYYYMMDD-XXXXXXXX` للاستخدام في الإيصالات والبحث والدعم والتدقيق | Must |
   364→| FR-LDG-006 | المعاملة تحفظ Snapshot لكل ما يفسّرها: الخدمة، العملة، المبلغ، الرسوم + `fee_rule_id` + `fee_version`، الأطراف، المزود، المرجع الخارجي، الأوقات، الحالة | Must |
   365→| FR-LDG-007 | التصحيح بعمليات Reversal/Adjustment مرتبطة بالمعاملة الأصلية؛ لا UPDATE للمعاملات المكتملة | Must |
   366→| FR-LDG-008 | كل عملية تمر عبر: صلاحيات → أهلية → فحص مخاطر → فحص حدود → تنفيذ → إشعار → إيصال | Must |
   367→| FR-LDG-009 | عند انقطاع الاتصال بعد إرسال الطلب: عند العودة يستعلم التطبيق عن حالة العملية الأصلية نفسها ولا ينشئ طلباً جديداً | Must |
   368→| FR-LDG-010 | وظيفة Reconciliation دورية (Job) تطابق: مجموع Ledger مقابل مجموع أرصدة المحافظ، وأي انحراف يولّد `RECONCILIATION_ALERT` | Must |
   369→| FR-LDG-011 | محرك الرسوم: قواعد مركزية (خدمة، عملة، مستوى مستخدم، منطقة، مدى مبلغ، ثابت/نسبة بحد أدنى/أقصى، فترة سريان) — لا رسوم مدفونة في كود التطبيق | Must |
   370→| FR-LDG-012 | محرك الحدود المركزي: لكل عملية/يوم/أسبوع/شهر + حد رصيد، حسب (المستخدم، مستوى KYC، العملة، الخدمة، المنطقة)، والفحص = الاستخدام الحالي + المطلوب ≤ الحد | Must |
   371→| FR-LDG-013 | محرك المخاطر: قواعد إشارات (جهاز جديد، محاولات PIN فاشلة، سرعة غير طبيعية، شذوذ الموقع، تكرار، حالة حساب مريبة) → النتائج: `ALLOW` / `REVIEW` / `BLOCK` | Must |
   372→| FR-LDG-014 | محرك الخدمات الموحّد: كل خدمة (شحن/فواتير/بطاقات…) معرفة بـ (فئة، مزود، حقول، تسعير، رسوم، حدود، سير عمل، تفعيل) — لا شاشات مستقلة بلا بنية | Must |
   373→| FR-LDG-015 | التكامل الخارجي عبر Adapter لكل مزود، مع مرجع خارجي + سياسة فشل واضحة (Pending / Retry / Reverse / Refund) | Must |
   374→| FR-LDG-016 | لا Retry أعمى للعمليات المالية؛ كل إعادة تعتمد على الحالة والمرجع الخارجي والIdempotency | Must |

   815→
   816→- **البساطة أولاً:** الأزرار الأساسية (تحويل/إيداع/سحب/دفع) بارزة في الرئيسية، والخدمات شبكة واضحة.

   830→# 8. التقنيات والمعمارية المقيدة
   831→
   832→| الطبقة | التقنية | ملاحظات |
   833→|---|---|---|
   834→| تطبيق الموبايل | Flutter + Dart | إلزامي (C-01)؛ بنية Presentation → Application/UseCases → Domain → Data |
   835→| الخادم | Node.js + NestJS | بديل: Laravel — يُثبَّت في وثيقة المعمارية (خطوة 3) |
   836→| قاعدة البيانات | PostgreSQL | معاملات ACID + Ledger؛ Migrations |
   837→| الكاش والجلسات | Redis | جلسات، كاش إعدادات، طوابير خفيفة |
   838→| المصادقة | OTP عبر مزود SMS + JWT/OAuth2 للجلسات | OTP الخادمي هو الأساس |

   840→| الخرائط | Google Maps أو Mapbox | خريطة الوكلاء |
   841→| الملفات | Storage موقّع (S3-متوافق) | مستندات KYC خاصة |
   842→| النشر | Docker + CI/CD | Google Play + App Store |
   843→| المراقبة | APM + Logs مركزية + Error Tracking | تنبيهات استباقية |

   845→**قيود معمارية إلزامية:**
   846→
   847→1. الواجهة لا تتعامل مع قاعدة البيانات مباشرة: UI → UseCase → Repository → API.
   848→2. كل تكامل خارجي عبر Adapter مع Idempotency وسياسة فشل.
   849→3. منطق الأعمال المالي في الخادم حصراً؛ Remote Configuration للسياسات والتحكم فقط (لا يتحول لغة برمجة موازية).
   850→4. كل كيان إداري يحمل created/updated/by/status؛ والحذف المنطقي للمحتوى فقط.

   856→## 9.1 Definition of Done (لكل وظيفة)
   857→
   858→```
   859→UI ✔ Backend ✔ Database ✔ Authorization ✔ Validation ✔ Error States ✔
   860→Loading States ✔ Success State ✔ Audit ✔ Notifications ✔ Reports ✔
   861→Admin Control ✔ Testing ✔
   862→وللوظائف المالية إلزامياً:
   863→Ledger ✔ Atomicity ✔ Idempotency ✔ Reconciliation ✔
   864→```

   866→## 9.2 سيناريوهات القبول الرئيسية (E2E)
   867→
   868→| # | السيناريو | النتيجة المقبولة |
   869→|---|---|---|
   870→| AC-01 | تسجيل ← KYC ← إيداع وكيل ← رصيد ← تحويل | استلام الطرف الآخر + رسوم مسجلة + إشعارات للطرفين + إيصال + ظهور في تقارير الإدارة + Ledger مطابق |
   871→| AC-02 | تحويل برصيد غير كافٍ | رفض فوري، لا حركة Ledger ولا رصيد، رسالة واضحة |
   872→| AC-03 | ازدواج طلب (نفس Idempotency مرتين) | عملية واحدة فقط، نفس النتيجة |
   873→| AC-04 | انقطاع إنترنت بعد إرسال التحويل | عند العودة: استعلام العملية الأصلية، لا إنشاء عملية جديدة |
   874→| AC-05 | تغيير الرسوم إدارياً | المعاملات القديمة بلقطتها، الجديدة بالقاعدة الجديدة |
   875→| AC-06 | تجاوز حد يومي | رفض بحد واضح، والاستخدام المحسوب صحيح |
   876→| AC-07 | مستخدم خارج النطاق | دخول واطلاع فقط (أو حسب سياسة) + إشعار + تسجيل تدقيق |
   877→| AC-08 | فشل مزود شحن بعد الخصم | Pending → Retry/Refund واضح، لا خصم غير مفسَّر، إشعار للمستخدم |
   878→| AC-09 | دور إداري A يحاول إجراء B بدون صلاحية | رفض خادمي (ليس إخفاء زر فقط) + Audit |
   879→| AC-10 | Reconciliation اليومي | انحراف → RECONCILIATION_ALERT مع تفاصيل، لا حذف بيانات |
   880→| AC-11 | إغلاق حساب برصيد | رفض الإغلاق حتى تصفية الرصيد؛ بعده CLOSED مع حفظ السجلات |
   881→| AC-12 | تجميد أمني | تجميد + إشعار + حالة مراجعة + Audit + مسار إفراج موثّق |

   902→## ملحق أ: خلاصة الآلات الحالة (State Machines)
   903→
   904→| الكيان | الحالات |
   905→|---|---|
   906→| الحساب | `PENDING → ACTIVE ⇄ RESTRICTED ⇄ FROZEN → SUSPENDED → CLOSED` |
   907→| KYC | `NOT_STARTED → PENDING → UNDER_REVIEW → APPROVED / REJECTED / EXPIRED / REQUIRES_UPDATE` |
   908→| المعاملة | `CREATED → VALIDATING → AUTHORIZED → PROCESSING → COMPLETED` (+ `FAILED / REJECTED / CANCELLED / EXPIRED / REVERSED / UNDER_REVIEW`) |
   909→| السحب | `CREATED → PENDING → AUTHORIZED → READY_FOR_COLLECTION → COLLECTED → COMPLETED` (+ رفض/انتهاء/إلغاء/عكس) |
   910→| الحوالة | `CREATED → PENDING_DELIVERY → DELIVERED → COMPLETED` (+ `EXPIRED / CANCELLED / REVERSED`) |
   911→| الأهلية | `ELIGIBLE / PENDING_REVIEW / RESTRICTED / OUTSIDE_SERVICE_AREA / BLOCKED` |
   912→| الخدمة | `ON / OFF / MAINTENANCE` |
   913→| النظام | `ACTIVE / MAINTENANCE / READ_ONLY / SERVICE_DEGRADED / BLOCKED` |
   914→| الوكيل | `ACTIVE / SUSPENDED / BLOCKED` |
