## ما هو هذا المشروع؟

تطبيق محفظة رقمية مغلق النظام النقدي: كل عملية مالية تمر بمحرك **دفتر مزدوج القيد** (Double-Entry) يضمن Σ=0 لكل معاملة — لا رصيد يُحدَّث مباشرة أبداً، بل قيود محاسبية متوازنة عبر دليل حسابات واحد. البطاقة المالية الأساسية (التحويل/الحوالات/الإيداع والسحب عبر الوكلاء) مكتملة، إلى جانب خدمات الدفع (فواتير، شحن رصيد، كروت شبكة، دفع تجار QR/POS)، الحصالة (أهداف ادخار)، صرف العملات، الحوالات الواردة، لوحة إدارة متعددة الأدوار، وبوابة وكيل.

## المزايا

**النواة المالية**
- تحويل فوري بين المستخدمين + قائمة مستفيدين + مشاركة إيصالات QR
- حوالات إلى غير المشتركين (إصدار → دفع لدى وكيل أو إلغاء/استرجاع)
- إيداع/سحب نقدي عبر وكلاء معتمدين (Float + عمولات + تسوية)
- حصالة ادخار بأهداف وإيداع/سحب/كسر
- صرف بين المحافظ الثلاث بأسعار FX خادمية
- كشف حساب وسجل عمليات كامل بالإيصالات

**الخدمات (Beta مكتملة وظيفياً)**
- فواتير (كهرباء/ماء/اتصالات/إنترنت/حكومي) بمعاينة ثم سداد
- شحن رصيد + كروت شبكة المشغلين
- دفع تاجر بالـ QR + شاشة POS للتاجر + رسوم على التاجر
- استلام حوالات واردة (قناة Remit-In) بإصدار إداري واستلام من العميل

**الإدارة والحوكمة**
- 6 أدوار فعلية: عميل، تاجر، وكيل، مدير نظام، امتثال KYC، دعم
- لوحة إدارة: نظرة عامة، مستخدمون (تجميد/إلغاء)، وكلاء، طابور KYC بعرض المستندات، العمليات المعلقة، معاملات، رسوم، حدود، FX، خدمات (إطفاء/تشغيل فوري)، أحداث أمنية، تدقيق، تذاكر
- بوابة الوكيل: طابور الإيداع/السحب، عمولات، نظرة عامة
- KYC برفع فعلي للمستندات (JPEG/PNG/WEBP ≤ 5MB بتحقق البايتات السحرية، تخزين 0600/0700)
- تذاكر دعم بمحادثات + إشعارات

**الأمان**
- مصادقة TOTP (RFC 6238) بدون SMS: تسجيل → QR لتطبيق المصادقة → رموز استرداد 8 × مرة واحدة؛ قفل 5 محاولات/15 دقيقة؛ إعادة إلحاق عبر الدعم برمز تفعيل R+7
- أسرار TOTP مشفّرة AES-256-GCM بمفتاح `APP_KEY` (fail-closed في الإنتاج)
- PIN بـ scrypt + قفل تصاعدي، جلسات منتهية الخادمي (7 أيام)، حد معدل على الدخول
- أحداث أمنية مسجّلة لكل محاولة + RBAC خادمي على كل مسار + `ADMIN_IP_ALLOWLIST` اختياري
- PWA بـ Service Worker حقيقي: صفحة أوفلاين، دورة تحديث بموافقة المستخدم، تنظيف كاش

## التشغيل السريع (تطوير)

**المتطلبات:** [Bun](https://bun.sh) ≥ 1.2 (وحده يكفي — يدير الحزم والسكربتات وTypeScript مباشرة).

```bash
git clone https://github.com/Mohammed503-qtb/Southern-wallet-QTBSW.git
cd Southern-wallet-QTBSW
bun install                      # الحزم (bun.lock مضمّن)
cp .env.example .env             # DATABASE_URL جاهزة للتطوير (APP_KEY اختياري هنا)
bunx prisma generate             # توليد عميل Prisma (إلزامي قبل أول تشغيل)
bun run db:push                  # إنشاء مخطط قاعدة البيانات (db/custom.db)
bun run db:seed:all              # (اختياري) بيانات تجربة متوازنة الدفاتر
bun run dev                      # http://localhost:3000
```

**بوابات الجودة قبل أي التزام:**
```bash
bun run lint        # ESLint — يجب أن يكون نظيفاً
bun run typecheck   # tsc --noEmit — صفر أخطاء
```

### حسابات التجربة (بعد البذور — للتطوير فقط)

| الهاتف | الدور | ملاحظة |
|---|---|---|
| `770000001` | عميل (موثّق KYC) | أحمد السُّقطري — رصيد وتاريخ معاملات |
| `770000020` | تاجر | متجر الجنوب للأغذية (عدن) |
| `770100001` | مدير نظام | لوحة الإدارة الكاملة |
| وكلاء آخرون | وكيل معتمد | عدن/حضرموت/لحج — لاختبار الإيداع/السحب |

**رمز الدخول TOTP لهذه الحسابات مشتق من `APP_KEY`** (سرّها يُزرع من المفتاح نفسه) — اطبع الرمز الحالي بـ:
```bash
bun run totp:code 770100001     # صالح 30 ثانية — أعد تشغيله عند كل دخول
```
> ⚠️ البذور وأداة الرموز **لبيئات التجربة فقط**. النشر العام يعمل بقاعدة نظيفة بلا أي حسابات مزروعة — المستخدمون الحقيقيون يملكون أسرار TOTP على أجهزتهم.

## النشر الإنتاجي

حزمة Docker كاملة (تطبيق + Caddy + HTTPS تلقائي + نسخ احتياطي/استرجاع): **الشرح المفصل خطوة بخطوة في [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md)**.

```bash
cp .env.production.example .env.production   # عدّل SW_DOMAIN وSW_ACME_EMAIL
docker compose up -d --build                 # المخطط يُنشأ تلقائياً عند أول إقلاع
```

**أول مدير في إنتاج نظيف:** يسجّل المسؤول حسابه من التطبيق عادياً (TOTP على جهازه) ثم:
```bash
docker compose exec app bun scripts/promote-role.ts 770XXXXXXX ADMIN
```

| المتغير | الإلزامية | الوظيفة |
|---|---|---|
| `DATABASE_URL` | ✓ | مسار SQLite (نسبي للتطوير، `/app/db/custom.db` داخل الحاوية) |
| `APP_KEY` | إنتاج ✓ | مفتاح AES-256-GCM لأسرار TOTP (≥ 32 محرفاً؛ يُولَّد تلقائياً في الحاوية ويُحفظ بـ 0600؛ **فقدانه = فقدان فك أسرار المصادقة**) |
| `ADMIN_IP_ALLOWLIST` | اختياري | قصر `/api/admin/*` على قائمة IP (RBAC-002) |
| `SW_DOMAIN` / `SW_ACME_EMAIL` | إنتاج ✓ | نطاق الشهادة وبريد Let's Encrypt |

## منهجية التحقق

لا يُعتبر أي عمل مكتملاً ببناء نظيف فقط — الدورة المعتمدة في هذا المشروع:
1. `bun run lint` + `bun run typecheck` نظيفان
2. مصفوفة curl حقيقية على كل مسار متأثر (نجاح/فشل/صلاحيات/حدود)
3. اختبار متصفح E2E للتدفقات (تسجيل → دخول → عمليات مالية → لوحات)
4. **`/api/admin/ledger-check`** → `balanced: true` وصفر مخالفات (العقد المالي)
5. CI على GitHub (lint + بناء إنتاجي standalone) أخضر
